# ماتریس تطبیق HOLLOO PRO+ با هلو شرکتی
آخرین بازبینی: 2026-11-15
مبنای مقایسه: اطلاعات عمومی منتشرشده برای هلو شرکتی ساده کد ۲۱، متوسط کد ۲۲ و پیشرفته کد ۲۳. امکانات دقیق ممکن است با ویرایش/ماژول و قرارداد پشتیبانی تغییر کند.

## وضعیت اجرایی فعلی
- «موجود» یعنی در کد مخزن مسیر قابل مشاهده دارد؛ به معنی تأیید پذیرش عملیاتی کامل نیست.
- «ناقص» یعنی بخشی از جریان وجود دارد اما همه چرخه‌ها، کنترل‌ها یا گزارش‌ها کامل نیست.
- «زیرساخت» یعنی migration یا مدل داده وجود دارد، اما اتصال/استقرار و تست انتها‌به‌انتها هنوز انجام نشده است.

| قابلیت | وضعیت HOLLOO PRO+ | فاصله/کار باقیمانده |
|---|---|---|
| خرید و فروش و فاکتور | ناقص | اندروید چندردیفی دارد؛ PWA هنوز تک‌ردیفی است؛ برگشت، پیش‌فاکتور، فاکتور رسمی/غیررسمی، تخفیف سطری و چاپ کامل لازم است |
| انبار و کاردکس تعدادی/ریالی | ناقص | گردش پایه و ارزش‌گذاری میانگین موزون هست؛ چندانباره، انتقال، انبارگردانی، کسری/اضافی و گزارش کاردکس کامل لازم است |
| بهای تمام‌شده واردات | ناقص/مزیت تخصصی | تخصیص پایه حمل/گمرک/سایر هزینه‌ها هست؛ رسید چندمرحله‌ای، کانتینر/پارت، اختلاف وزن، ارز و تسویه تأمین‌کننده باید تکمیل شود |
| سرفصل و سند حسابداری | ناقص | مدل سند و کنترل تراز در اندروید وجود دارد؛ گردش کامل کل/معین/تفصیلی، سند دستی، موقت/دائم، اصلاح/ابطال و بستن حساب‌ها لازم است |
| دفتر کل و معین | ناقص | گزارش‌های موجود جایگزین دفتر کل و مرور حساب نیستند |
| تراز آزمایشی ۲/۴/۶/۸ ستونی | ناقص | گزارش استاندارد و قابل تطبیق تولید نشده |
| سود و زیان و ترازنامه | ناقص | PWA فقط سود ناخالص مدیریتی دارد؛ صورت‌های مالی مبتنی بر مانده حساب‌ها لازم است |
| سود هر فاکتور/کالا/طرف حساب | بخشی موجود | گزارش مدیریتی PWA اضافه شده؛ هزینه‌های عملیاتی، تخفیف/مالیات و اسناد برگشتی باید در محاسبه لحاظ شوند |
| دریافت و پرداخت، صندوق و بانک | ناقص | گردش پایه وجود دارد؛ انتقال بین حساب‌ها، تنخواه، حواله، تطبیق و مغایرت بانکی کامل لازم است |
| چرخه کامل چک | ناقص | ثبت/تغییر وضعیت ساده وجود دارد؛ واگذاری، وصول، برگشت، خرج، ضمانتی/امانی، سررسید و راس چک لازم است |
| سطح دسترسی کاربران | زیرساخت | نقش‌ها و RLS در SQL نوشته شده؛ استقرار Supabase، احراز هویت و کنترل دسترسی UI/API لازم است |
| ممیزی عملیات | زیرساخت | audit migration نوشته شده؛ باید روی Supabase واقعی اجرا و با رخدادهای عملی تست شود |
| همگام‌سازی Android/PWA | زیرساخت | schema و RPC اولیه موجود؛ adapter، صف آفلاین، حل تعارض، احراز هویت و sync واقعی هنوز نیست |
| خروجی Excel/CSV و پشتیبان | بخشی موجود | پشتیبان JSON و خروجی CSV گزارش مدیریتی در PWA؛ خروجی‌های استاندارد همه گزارش‌ها لازم است |
| چندکاربره/چندشرکتی | زیرساخت | سازمان/عضویت در schema هست؛ tenant isolation و تست چندکاربره عملیاتی نشده |
| گزارش عملکرد کاربران/واسطه/پورسانت | ناقص | مدل و گزارش عملیاتی کامل نشده |
| بارکد، چاپ فاکتور/چک، پیامک | ناقص/ندارد | پیاده‌سازی و اتصال سخت‌افزار/سرویس لازم است |

## ترتیب تکمیل
1. دفتر کل، گردش حساب و تراز آزمایشی؛
2. چرخه کامل اسناد و فاکتورهای چندردیفی در PWA؛
3. انبارهای متعدد، حواله و انبارگردانی؛
4. چک و بانک و مغایرت‌گیری؛
5. صورت‌های مالی و گزارش‌های سود دقیق؛
6. اتصال واقعی Supabase و کنترل دسترسی؛
7. تست پذیرش، امضای پایدار APK و تست ارتقا؛
8. تطبیق نهایی با نسخه/کد دقیق خریداری‌شده هلو.

## محدودیت استقرار
Migrationهای Supabase تا زمان اجرا روی پروژه واقعی فعال نیستند. برای اتصال باید Project URL و publishable/anon key ارائه شود؛ هرگز service_role یا رمز دیتابیس را ارسال نکنید. امضای Release APK نیز هنوز پیکربندی نشده است.
