# راه‌اندازی همگام‌سازی Supabase برای HOLLOO PRO+

این پروژه برای همگام‌سازی APK و PWA از Supabase استفاده خواهد کرد. این commit زیرساخت امن سمت پایگاه داده را آماده می‌کند؛ اتصال کلاینت‌ها تا زمان ساخت پروژه Supabase و دریافت Project URL و کلید عمومی (publishable/anon) کامل نمی‌شود.

## راه‌اندازی پروژه
1. در Supabase یک پروژه جدید بسازید و Region نزدیک به کاربران/سرورهای شما انتخاب کنید.
2. از SQL Editor محتوای فایل `supabase/migrations/001_shared_sync.sql` را اجرا کنید.
3. در Authentication، روش Email فعال باشد. کاربران باید قبل از همگام‌سازی وارد حساب شوند.
4. Project URL و کلید عمومی publishable/anon را برای پیکربندی کلاینت‌ها نگه دارید.
5. هرگز `service_role` key یا رمز دیتابیس را در APK، PWA، مخزن Git یا فایل‌های عمومی قرار ندهید.

## مدل امنیت و همگام‌سازی
- داده‌ها با organization_id جدا می‌شوند.
- دسترسی به هر سازمان از طریق عضویت و نقش کنترل می‌شود.
- کلاینت‌ها فقط رکوردهای سازمان عضو را می‌خوانند.
- نوشتن فقط از RPC امن `apply_sync_batch` انجام می‌شود.
- هر رکورد UUID و version دارد؛ کلاینت باید base_version را بفرستد.
- تعارض نسخه باعث rollback کل batch می‌شود؛ کلاینت باید نسخه سرور را دریافت و تعارض را به کاربر/قواعد دامنه ارجاع دهد.
- حذف به شکل tombstone ثبت می‌شود؛ حذف فیزیکی از سمت کلاینت مجاز نیست.
- هر batch حداکثر ۲۰۰ تغییر دارد.

## محدودیت فعلی
این commit فقط schema و RPC سمت Supabase را آماده می‌کند؛ هیچ پروژه Supabase به حساب کاربر متصل نشده و هیچ داده‌ای هنوز sync نمی‌شود. برای فعال‌سازی واقعی، Project URL و publishable/anon key لازم است. منطق merge و صف آفلاین کلاینت‌ها در فاز بعدی پیاده‌سازی و تست می‌شود.


## 7) سخت‌سازی دسترسی و ثبت رویدادها

پس از اجرای `001_shared_sync.sql`، فایل `migrations/002_role_audit_hardening.sql` را نیز در SQL Editor اجرا کنید.

- نقش `viewer` فقط خواندنی است.
- نقش `sales` فقط مجاز به همگام‌سازی اشخاص و فاکتورهاست.
- نقش `warehouse` فقط مجاز به همگام‌سازی کالا، گردش انبار و رسید/سفارش واردات است.
- نقش‌های `owner`، `admin` و `accountant` دسترسی نوشتن به همه انواع داده تعریف‌شده دارند.
- رویدادهای ایجاد، ویرایش و حذف منطقی در `audit_events` ثبت می‌شوند؛ کاربران عادی امکان تغییر یا حذف این سوابق را ندارند.

این Migration نیز تا زمان اجرا در پروژه Supabase شما، صرفاً در مخزن کد قرار دارد و روی سرور فعال نشده است.
